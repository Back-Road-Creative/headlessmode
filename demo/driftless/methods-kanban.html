Kanban

A way of managing ongoing work by making it visible, capping how much runs at once, and improving steadily.

Source: Essential Kanban Condensed, 2016 edition (Anderson & Carmichael, Lean Kanban University).

Event

Kanban Meeting
A short daily meeting where the team looks at the board and plans its next step.

Map

  • See it on the map

Running it well:

  • It stays short, stays focused on the board, and ends with clear next steps rather than open discussion.
  • It happens at the same time and place every day so it becomes a habit, not an event to schedule around.

Going wrong looks like:

  • It turns into a long status meeting where each person narrates their day instead of the team looking at the board together.
  • It gets skipped whenever the team feels busy, which is exactly when it would help most.
Replenishment Meeting
A regular meeting where new work is chosen and pulled onto the board.

Map

  • See it on the map

Running it well:

  • It runs on its own cadence, separate from the daily meeting, and only pulls in work that is genuinely ready.
  • What gets pulled in is limited to what the board's own capacity can actually absorb next.

Going wrong looks like:

  • It gets skipped, so new work is added to the board ad hoc whenever someone thinks of it.
  • Items are pulled in before they are ready, so they stall on the board waiting for information that should have been settled first.

Map

  • See it on the map

Running it well:

  • The board's columns match the path work actually follows, not an idealized version of it.
  • Every piece of work in progress has a card on the board, with nothing moving through a side channel the board can't see.

Going wrong looks like:

  • Hidden work never gets a card, so the board stops reflecting what people are actually doing.
  • The board is updated in a weekly meeting instead of as work actually moves, so it is always stale.
Limit Work in Progress
A hard cap on how many items each stage of work may hold at once.

Map

  • See it on the map

Running it well:

  • Each column's limit is a hard cap that holds even when it would be convenient to start one more thing.
  • When a column is at its limit, the team helps clear it rather than starting new work elsewhere.

Going wrong looks like:

  • The limit gets raised whenever it becomes inconvenient, until it no longer limits anything.
  • Limits are set once and never revisited even as the team's capacity changes.

Running it well:

  • Cycle time and where items stall are watched as a trend over many items, not judged from one anecdote.
  • A stall gets attention while the item is still on the board, not after it finally ships.

  • Flow metrics are collected and displayed but nobody acts on what they show.
  • Attention only goes to the newest or loudest item, not the one that has actually stalled longest.

Running it well:

  • The rules for moving work forward are written down somewhere everyone can reach, not kept in one person's head.
  • A dispute about whether an item can move gets settled by pointing at the written policy.

Going wrong looks like:

  • The real rule for moving work only exists as one senior person's judgment, so decisions vary by who is asked.
  • Policies are written once and never checked against how work is actually moving.

Board Policy Template

  1. Name every column on the board and what 'done' means to leave it for the next one.
  2. Set an explicit work-in-progress limit for each column that needs one.
  3. State the pull rule: a column pulls from upstream only when it has spare capacity.
  4. Write down what makes an item eligible to enter the board at all.
  5. Record how blocked work is marked and who is responsible for unblocking it.
  6. Set the cadence for reviewing and changing these policies.
