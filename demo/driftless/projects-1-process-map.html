Tailoring — Predictive

  • 4.5 Monitor and Control Project Work — Runs on: predictive baseline — Overall project performance is compared against the approved baseline no matter how the day-to-day work is tailored.
  • 4.6 Perform Integrated Change Control — Runs on: predictive baseline — Every plan change goes through one request-and-approval chain, so there is only ever one way to change the plan.
  • 5.5 Validate Scope — Runs on: predictive baseline — Finished work is accepted against the scope baseline the project approved.
  • 5.6 Control Scope — Runs on: predictive baseline — Scope changes are measured as variance from the approved scope baseline.
  • 6.6 Control Schedule — Runs on: predictive baseline — Progress is measured as variance from the approved schedule baseline.
  • 7.4 Control Costs — Runs on: predictive baseline — Spend is tracked against the approved cost baseline, however the work that earns it gets done.
  • 8.3 Control Quality — Runs on: predictive baseline — Quality is checked against the standard set out in the quality baseline.
  • 9.6 Control Resources — Runs on: predictive baseline — Resource use is tracked against the plan the project approved.
  • 10.3 Monitor Communications — Runs on: predictive baseline — Communications are checked against the plan the project approved.
  • 11.7 Monitor Risks — Runs on: predictive baseline — Risks are reviewed against the response plan the project approved.
  • 12.3 Control Procurements — Runs on: predictive baseline — Procurement performance is measured against the agreement the project approved.
  • 13.4 Monitor Stakeholder Engagement — Runs on: predictive baseline — Stakeholder engagement is checked against the plan the project approved.

Sign off or waive a process

Signing off records the process as approved-done; waiving tailors it out, dropping it from every completeness figure above. Both are ledger entries, signed by whoever is signed in — a reversal is a new decision, never an edit.
